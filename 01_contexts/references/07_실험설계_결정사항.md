## 4. 실험 프로토콜

### System Prompt

**Gemini 대화에서 제안된 버전:**
> "You are a Hyperledger Fabric Security Expert. Analyze the following Go chaincode for security vulnerabilities. Focus on: Non-deterministic execution, Global variables, Phantom reads."

**실제 02_run_audit.py에 구현된 버전 (실측):**
> "You are a Hyperledger Fabric Security Expert. Analyze the following Go chaincode for security vulnerabilities. Focus on: access control issues, input validation flaws, read-after-write conflicts (phantom reads), private data leakage, non-deterministic operations, and insecure key management. For each vulnerability found, provide: 1. Vulnerability type 2. Severity (Critical/High/Medium/Low) 3. Affected code location (function name and line reference) 4. Description of the issue 5. Recommended fix. If no vulnerabilities are found, state 'No vulnerabilities detected.'"

> **참고**: 실제 스크립트의 프롬프트가 Gemini 제안보다 범위가 넓음 (6개 항목 + 출력 형식 지정). 이 차이는 Llama의 오탐(access control, input validation 등)이 프롬프트에 의해 유도된 측면이 있음을 시사.

### 실험 흐름
1. 모델 로드 (`Llama(model_path=..., n_gpu_layers=-1, n_ctx=4096-8192)`)
2. `.go` 파일 순회 (dataset 폴더)
3. 각 파일에 대해 System Prompt + 코드 전달
4. 응답 수집 → CSV 저장 (`audit_log.csv`)
5. 모델 교체 후 반복

### 평가 기준
| 메트릭 | 설명 |
|:------|:-----|
| 탐지 성공(Pass) | 취약점 이름이나 위치를 맞췄는가 (O/X) |
| 오탐(False Positive) | 없는 버그를 있다고 우겼는가 (O/X) |

## 5. 논문 방어 논리 (Defense Logic) — 대화에서 확정된 3단 구조

### 방어 1: "기존 HLF 연구는 너무 딱딱하다" (vs VulFinder)
- Fact: VulFinder(2025)는 KG 기반, 사전 정의된 패턴만 탐지
- Attack: "신종 공격이나 비즈니스 로직 미묘한 오류는 패턴 매칭으로 못 잡음. LLM의 추론 능력 사용"

### 방어 2: "기존 LLM 연구는 번지수 틀렸다" (vs EVuLLM)
- Fact: EVuLLM(2025)은 이더리움(Solidity)만 대상
- Attack: "기업용 블록체인은 Go 언어. Solidity 잘하는 모델이 Go의 Goroutine/포인터 못 잡음. Go 특화 모델(Qwen-Coder) 검증"

### 방어 3: "왜 굳이 로컬인가? 프라이버시!" (Justification)
- Fact: 기업 체인코드는 1급 기밀
- Attack: "GPT-4 좋은 건 알지만 기업 데이터를 OpenAI에 넘길 수 없음. 온프레미스 sLM이 답"

## 6. 논문에 삽입할 핵심 문장 (대화에서 제시됨)

### Methodology 정당화
> "While dynamic fuzzing methodologies like Echidna excel in the deterministic EVM environment by detecting runtime crashes, they are methodologically blind to the 'silent' consensus failures inherent in Hyperledger Fabric's Execute-Order-Validate (EOV) architecture."

### Dataset 정당화 (Gemini 원문 — 실제 구현은 6종)
> "Since public datasets for vulnerable HLF chaincodes are scarce, as noted in recent studies, we generated a synthetic dataset focusing on the top 5 distinct anti-patterns of Hyperledger Fabric."

> **실측 참고**: Gemini 원문은 "top 5"로 기술했으나, 최종 구현은 6종("The 6 Deadly Sins")으로 확정됨. 논문 본문에서는 "top 6"으로 수정 필요.

### Limitation
> "While dynamic analysis methods like Fuzzing (e.g., OSS-Fuzz) are effective for detecting runtime crashes, they often fail to identify non-deterministic logic flaws that do not cause immediate crashes but violate consensus. Our Local sLM approach focuses on Semantic Static Analysis to bridge this gap without requiring complex test harnesses."
